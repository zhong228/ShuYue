## 本次新增修正

- [x] Google 登入回呼：`Cj19Q59kC3ozuJpn20g58F` 的 Last Exception Backtrace 明確落在 `OIDAuthorizationSession.resumeExternalUserAgentFlowWithURL:`（line 133）→ `GIDSignIn.handleURL:`。AppAuth 2.0.0 在已完成／取消的 flow 收到遲到回呼時拋出 NSException；Swift 無法 catch 這個 ObjC 例外。更新 GoogleSignIn 至 10.0.0，Xcode 解析 AppAuth 3.0.0、GTMAppAuth 6.0.0；其他 resolved pins 不變。修正發生在 SDK 的流程檢查，沒有攔截或吞掉正常 Google 登入回呼。
- [x] 移除下載：`DF3Jm2JaGsfRyv7x4bDP3B` build 91 的完整 exception stack 指向 `OfflineDownloadManager.remove → BookStore.clearOnlineDownload → Published/SwiftUI → PlaceholderPageViewController.viewDidLoad → NSLayoutConstraint.activate`。`clearOnlineDownload` 原先沒有 actor 隔離，跨 await 後在背景發布 UI 狀態；入口改成 `@MainActor`，磁碟刪除仍委派 OfflineChapterStoring，並保留 await 後依 book ID 重新定位的保護。

- [x] SwiftSoup DOM 所有權：原有 thread-local cache 足以隔離同步 CSS 提取，但 `LegadoJsoupBridge.parse` 返回的 JS wrapper 會保留 Document，超過原始同步呼叫的生命週期。serial queue 並不固定 OS thread，另一個 extractor／JS context 可重用相同 thread-local Document。現在每個 JSContext 在 configureContext 時建立自己的 bridge/cache；timeout 建立的新 context 也不與舊 context 共用。仍使用相同 JsoupDocumentCache／SwiftSoup 解析實作，原生同步提取仍用 thread-local cache。

上游依據：[AppAuth 2.1.0 回呼例外修正](https://github.com/openid/AppAuth-iOS/releases/tag/2.1.0)、[AppAuth 3.0.0 的 Xcode 27／Swift 匯入修正](https://github.com/openid/AppAuth-iOS/releases/tag/3.0.0)、[GoogleSignIn 10.0.0](https://github.com/google/GoogleSignIn-iOS/releases/tag/10.0.0)。上游亦取消 ASWebAuthenticationSession 無法啟動時的外部 Safari fallback，改回報錯誤；並未在 App 另造登入替代路徑。最低支援版本仍是 iOS 17。
